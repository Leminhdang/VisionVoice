Tổng quan

VisionVoice là app camera voice-first tiếng Việt cho người khiếm thị, gồm đúng 3 chức năng:

  • Mô tả ảnh — chụp (nút, giọng nói, phím âm lượng) hoặc chọn từ gallery → gửi Gemini → đọc caption bằng TTS.
  • Hỏi đáp về ảnh — chat multi-turn với Gemini về ảnh vừa chụp, điều khiển hoàn toàn bằng giọng nói + push-to-talk.
  • Dò vật cản — vòng lặp quét real-time bằng TFLite (EfficientDet-Lite0) object detection on-device, cảnh báo theo mức độ (safe/warning/danger).

Stack: Expo SDK 56 (new architecture, expo-dev-client — không chạy được trên Expo Go vì có native module Firebase + VisionCamera + TFLite), React Native 0.85.3, React 19.2.3, TypeScript 6.0 strict, React Navigation native-stack (4 màn hình), Firebase AI Logic (@react-native-firebase/ai) gọi Gemini kèm App Check, jest-expo cho unit test (src/services/__tests__, src/state/__tests__). Không có Redux/Zustand — state duy nhất là SettingsContext + useReducer trong captureMachine.ts.

Chỗ đứng của audioSession.ts: đây là module DUY NHẤT được đụng cả ASR lẫn TTS (xem bất biến half-duplex). Màn hình muốn nói → speakExclusive(); muốn nghe → startListening()/stopListening(); Q&A đóng băng mic khi chờ Gemini bằng setSuspended(). Duy nhất tts.stop() được gọi thẳng từ ngoài (barge-in, cleanup).

4 luồng chính

1. Mô tả ảnh — từ trigger đến đọc xong + giữ result

  1. Trigger: nói "chụp ảnh" (useVoiceControl → voiceIntents.ts:parseIntent), phím âm lượng (useVolumeButtonPTT), nút shutter, hoặc gallery. 3 trigger đầu đi qua HomeCameraScreen.tsx:captureFlow → useDebounceCallback (leading-edge, CAPTURE_DEBOUNCE_MS = 2000).
  2. runCaptureFlow: hapticCapture() + playShutter(), dispatch('CAPTURE_START') — state machine captureMachine.ts đi idle → capturing (chỉ chụp được khi canCapture, tức idle).
  3. imagePipeline.ts:captureAndPrepare: photoOutput.capturePhoto({ enableShutterSound: false }) → photo.saveToTemporaryFileAsync() → prepareFromUri: resize width 800, compress 0.5, JPEG + base64 → PreparedImage. Gallery đi thẳng prepareFromUri(pickedUri).
  4. analyzeAndSpeak: dispatch('ANALYZE_START'), đọc CAPTURE.ANALYZING (không await), rồi gemini.ts:describeImage(image, captureId) — generateContent([imagePart, DESCRIBE_PROMPT]); quota/404 thì describeWithFallback thử lại bằng GEMINI_FALLBACK_MODEL.
  5. dispatch('SPEAK_START') → await audioSession.speakExclusive(description) → dispatch('DONE').
  6. Giữ result: setLastImage/setLastDescription → hasResult = true → render màn kết quả (CaptionPanel + 3 nút: hỏi về ảnh / chụp mới / đọc lại), đọc CAPTURE.RESULT_HINT. Ở màn kết quả, lệnh "chụp" chạy handleNewCapture (xoá result, quay về camera) chứ KHÔNG chụp ngay.
  7. Lỗi: GeminiError.kind → ERRORS[kind] đọc lên, dispatch('ERROR') về idle. gemini.ts không bao giờ trả text lỗi giả làm caption.

2. Hỏi đáp multi-turn

  1. HomeCameraScreen:openQA → navigation.navigate('QASession', { image, caption }) — PreparedImage (đã có base64) đi qua route params.
  2. QASessionScreen hai tầng: tầng ngoài đọc NAV.QA XONG mới mount QASessionActive — vì tts.speak mặc định flush, mount sớm thì QA.ASK_PROMPT cắt ngang lời giới thiệu.
  3. useQASession mount: gemini.ts:createQASession(image) → startChat(); đọc QA.ASK_PROMPT → beginListeningImpl (âm báo playListenStart + audioSession.startListening).
  4. Final transcript → processTranscript: parseIntent ra 'back'/'stop' → gọi onExitIntent (KHÔNG gửi Gemini); còn lại → askQuestion.
  5. Ảnh gửi đúng 1 lần: trong createQASession, lượt đầu (isFirstTurn) gửi [imagePart, question], các lượt sau chỉ gửi text — ChatSession tự giữ context hội thoại.
  6. Khi chờ Gemini: audioSession.setSuspended(true) (mic đóng băng). Có answer → speakExclusive(answer) → setSuspended(false) → auto-relisten sau QA_RELISTEN_DELAY_MS = 800.
  7. Barge-in PTT: đè vùng mic (onPressIn) hoặc bấm phím âm lượng → interrupt(): tts.stop() + setSuspended(false) + nghe lại NGAY — cắt ngang câu trả lời đang đọc. Guard statusRef.current !== 'answering' trong askQuestion ngăn schedule relisten đè lên phiên nghe do barge-in mở.
  8. Thoát: end() → dispose() chat + stopListening(); blur/unmount cũng end() qua useFocusEffect.

3. Vòng lặp vật cản

  1. ObstacleModeScreen: useKeepAwake(), đọc NAV.OBSTACLE; useObstacleScanner(cameraRef, { active: isFocused }) — blur là vòng quét dừng hẳn.
  2. Mỗi cycle(): photoOutput.capturePhoto({ enableShutterSound: false }) → detectFromPhoto(photo) — pixel buffer BGRA→RGB resize 320×320 → TFLite model.runSync().
  3. detectFromPhoto(photo) — TFLite on-device, model EfficientDet-Lite0 loaded qua loadTensorflowModel.
  4. obstacleDetector.ts:assessDetections(objects, frameSize, sensitivity): lọc score ≥ OBSTACLE_SCORE_MIN (0.35, labels rỗng tính score 1), tâm bbox phải nằm trong dải giữa CENTER_BAND_WIDTH_RATIO[sensitivity]; severity theo areaRatio: danger ≥ 0.35, warning ≥ 0.18.
  5. createAnnouncementPolicy().shouldAnnounce(result, now): cooldown danger 2000ms / warning 3000ms (ANNOUNCE_COOLDOWN_MS), leo thang LÊN danger bỏ qua cooldown, safe chỉ đọc đúng lúc transition vào safe.
  6. announceAssessment (trong useObstacleScanner.ts): danger = playDanger + haptic + speakExclusive(OBSTACLE.DANGER, { flush: true }); warning kèm label tiếng Việt nếu map được qua OBSTACLE.LABEL_VI.
  7. finally: deleteFrameFile(frameUri) xoá file khung hình tạm (best-effort) + scheduleNext — chu kỳ kế tiếp delay max(0, OBSTACLE_SCAN_INTERVAL_MS(900) − elapsed), không bao giờ chồng nhau. Frame lỗi chỉ warn, loop sống tiếp.
  8. Cleanup bằng run-token (Symbol): cycle đang bay của lần kích hoạt cũ không thể resume tạo loop thứ hai.

4. Khởi động app

  1. App.tsx useEffect: tts.ts:initTts() — đọc + theo dõi trạng thái screen reader (TalkBack/VoiceOver) qua AccessibilityInfo; singleton trọn đời, không teardown. Đang bật screen reader thì speak() route qua announceForAccessibility thay vì expo-speech.
  2. firebase.ts:initFirebase() — chỉ lo App Check: provider 'debug' khi __DEV__, 'playIntegrity' (Android) / 'appAttestWithDeviceCheckFallback' (iOS) khi prod. Fail thì warn và app vẫn boot; instance được gemini.ts:getAiInstance lấy qua getAppCheckInstance().
  3. DetectionRoot: loadTensorflowModel() nạp file efficientdet_lite0.tflite vào bộ nhớ. Model ref được truyền qua context cho useObstacleScanner. Chú ý: model chỉ nạp một lần khi mount, không nạp lại mỗi render.
  4. RootNavigator: initialRouteName="HomeCamera", headerShown: false, animation: 'none'.
  5. HomeCameraScreen → usePermissionBootstrap: nói TRƯỚC khi xin quyền — speak(PERMISSIONS.MIC_REQUEST) → chờ PERMISSION_PROMPT_DELAY_MS = 3000 (cho user kịp định vị dialog hệ thống) → requestMicPermission(); camera lặp lại tương tự (mic trước, camera sau). Từ chối KHÔNG block: ready vẫn true, app chạy degraded.
  6. ready → đọc PERMISSIONS.WELCOME, checkVietnameseVoice() cảnh báo nếu máy thiếu giọng vi; screen effect chạy focusNow() + announceScreen(NAV.HOME) + speakExclusive(NAV.HOME).

Bất biến half-duplex

Vì sao: ASR chạy continuous — nếu mic mở trong lúc TTS nói, mic nghe chính giọng TTS và transcript đó thành lệnh/câu hỏi mới (app tự nói chuyện với chính nó). Loa và mic phải luân phiên: half-duplex.

  • Luật "chỉ speakExclusive": audioSession.ts là module duy nhất đụng cả ExpoSpeechRecognitionModule lẫn tts. Trình tự trong speakExclusive: set isSpeaking = true → hardStopRecognition() (dùng abort(), không chờ final result) → await tts.speak(text) → scheduleRestart(TTS_GUARD_DELAY_MS).
  • Guard 400ms (TTS_GUARD_DELAY_MS = 400): sau khi TTS xong, đuôi âm thanh/echo vẫn còn lọt vào buffer ASR — mic chỉ mở lại sau 400ms, và isSpeaking chỉ hạ về false bên trong callback của scheduleRestart.
  • Vứt transcript khi đang nói: handleResult return sớm khi isSpeaking — mọi result đến trong lúc nói hoặc trong guard window bị discard, không bao giờ chạm callback màn hình. Đây là chốt chặn thứ hai phòng khi abort() chưa kịp có hiệu lực.
  • iosCategory fix: startRecognition truyền iosCategory: { category: 'playAndRecord', categoryOptions: ['defaultToSpeaker', 'allowBluetooth'] } — mặc định iOS khi record sẽ chuyển output sang loa thoại (earpiece) làm TTS nhỏ gần như không nghe được; defaultToSpeaker giữ loa ngoài.
  • setSuspended(true/false): tầng nghỉ riêng cho Q&A khi chờ Gemini — giữ wantListening để resume được, resume cũng đi qua guard 400ms. Restart chỉ có MỘT slot (scheduleRestart luôn thay timer cũ), không bao giờ có hai timer đua nhau mở mic.

audioSession.ts — điều phối half-duplex ASR/TTS

Module DUY NHẤT được đụng cả ASR (expo-speech-recognition) lẫn TTS. Khi TTS nói (và trong guard window sau đó) mọi transcript bị bỏ — app không nghe chính nó.

setSuspended(value: boolean) => voidtrue: pause; false: resume sau guard delay

  • Timer restart — 1 slot duy nhất (scheduleRestart luôn thay slot cũ):
    Sự kiệnDelayHằng số

    ASR event error (trừ aborted tự gây)2000msASR_RESTART_ON_ERROR_MS

obstacleDetector.ts — logic vật cản thuần

Pure logic (không React/Expo import). Type DetectedObject là structural alias tương thích với output của TFLite EfficientDet-Lite0 (originX, originY, width, height, label, score).

ExportChữ kýHành vi
assessDetections(objects, frame: FrameSize, sensitivity) => AssessmentLọc + chấm mức độ 1 frame; trả {severity, label, areaRatio}
createAnnouncementPolicy() => AnnouncementPolicyGate stateful (closure): shouldAnnounce(assessment, now)
  • Lọc: object phải có score ≥ OBSTACLE_SCORE_MIN (0.35; labels rỗng = score 1, vẫn là vật cản) VÀ tâm-x bbox nằm trong dải trung tâm.
  • Công thức: areaRatio = (size.x × size.y) / (frame.width × frame.height). Severity cao nhất thắng, hoà thì areaRatio lớn hơn thắng. safe luôn label: null.
  • Ngưỡng:
    areaRatioSeverity
    ≥ 0.35 (DANGER_AREA_RATIO)danger
    ≥ 0.18 (WARNING_AREA_RATIO)warning
    còn lạisafe
  • Dải trung tâm theo sensitivity (CENTER_BAND_WIDTH_RATIO × frame.width, canh giữa): low 0.25 · medium 0.4 · high 0.5. Nhạy hơn = dải rộng hơn = bắt nhiều object hơn.
  • Policy cooldown (ANNOUNCE_COOLDOWN_MS): danger 2000ms, warning 3000ms tính từ lần đọc severity đó. Escalation lên danger (severity trước ≠ danger) bỏ qua cooldown 1 lần; danger kéo dài thì theo cooldown 2s. safe chỉ đọc lúc chuyển vào safe rồi im. State chỉ cập nhật khi được phép đọc → transition bị chặn được retry ở frame sau.

State

captureMachine.ts — state machine luồng chụp

AppPhase = 'idle' | 'capturing' | 'analyzing' | 'speaking'. Hàm thuần transition(phase, event) làm reducer cho hook useCaptureMachine() (trả { phase, dispatch, canCapture, isProcessing }). ERROR/RESET từ mọi phase về idle; event không hợp lệ → giữ nguyên phase.

phase \ eventCAPTURE_STARTANALYZE_STARTSPEAK_STARTDONEERRORRESET
idlecapturing———idleidle
capturing—analyzing——idleidle
analyzing——speaking—idleidle
speaking———idleidleidle

("—" = giữ nguyên phase.) Helpers: canCapture(phase) = phase === 'idle'; isProcessing(phase) = phase !== 'idle' — dùng để chặn double-trigger từ voice/volume/button.

strings.ts và intents

Cấu trúc nhóm chuỗi

src/constants/strings.ts gom toàn bộ chuỗi user-facing (100% tiếng Việt) — màn hình không hardcode chuỗi:

  • GEMINI_SYSTEM_INSTRUCTION, DESCRIBE_PROMPT — prompt gửi Gemini.
  • KEYWORDS — từ khoá voice intent (bảng dưới).
  • NAV — lời dẫn khi vào mỗi màn, đọc bằng TTS + announceScreen.
  • STATE, CAPTURE, HOME, QA, OBSTACLE, SETTINGS, SCREEN_TITLES, PERMISSIONS — chuỗi theo màn; vài entry là hàm template (QA.TURN_USER(text), OBSTACLE.WARNING_WITH_LABEL(label)).
  • COCO_LABEL_VI — map 80 nhãn COCO Anh → Việt (person→người, chair→ghế, backpack→ba lô…).
  • ERRORS — key thường (network/blocked/quota/unknown) khớp đúng GeminiError.kind để tra ERRORS[err.kind]; key HOA (NO_VI_VOICE, GALLERY) là lỗi rời.

Intent → keyword

Parser ở src/services/voiceIntents.ts. Mọi so khớp chạy trên chuỗi đã qua normalizeVietnamese(): NFD bỏ dấu, đ→d, lowercase, gộp khoảng trắng. Match theo ranh giới từ (pad hai đầu bằng space rồi includes), không substring trần — "thời tiết" → "thoi tiet" chứa "hoi", includes trần sẽ match nhầm question.

Ưu tiênIntentKeyword mẫu (có dấu + không dấu)
1stopdừng, dừng lại, dung lai, im lặng, im lang, tắt, tat
2backquay lại, quay lai, trở về, tro ve, thoát, thoat
3questionhỏi, hoi, đặt câu hỏi, dat cau hoi
4repeatđọc lại, doc lai, nghe lại, nghe lai, nói lại, noi lai
5obstaclevật cản, vat can, dò vật cản, do vat can, dò đường, do duong, cảnh báo, canh bao
6settingscài đặt, cai dat, thiết lập, thiet lap
7capturechụp, chụp ảnh, chup, chup anh
—unknownkhông match gì → bị bỏ qua (không handler)

Thứ tự ưu tiên = mảng INTENT_PRIORITY, duyệt tuần tự, match đầu tiên thắng. capture đứng cuối có chủ đích: "chụp" xuất hiện trong nhiều câu — "dừng chụp" phải ra stop. stop/back đứng đầu vì lệnh thoát/dừng phải thắng mọi thứ.

Quy tắc thêm keyword mới

  • Bắt buộc thêm cả bản không dấu ("chụp ảnh" + "chup anh") — ASR trả về cả hai biến thể tuỳ thiết bị. normalizeVietnamese đã bỏ dấu nên hai bản trùng nhau sau chuẩn hoá, nhưng convention repo là khai báo đủ để đọc KEYWORDS thấy ngay app hiểu gì.
  • Chỉ sửa KEYWORDS trong strings.ts — NORMALIZED_KEYWORDS tự build lúc load module.
  • Keyword 1 từ ngắn/dễ trùng (kiểu "hoi") phải thử với các câu thường gặp trước khi thêm.
  • Thêm intent mới: thêm key vào KEYWORDS, thêm literal vào union VoiceIntent, chèn đúng vị trí trong INTENT_PRIORITY — mặc định trước capture.

Setup từ clone

Repo dùng Expo dev client (native module: RNFB, VisionCamera, TFLite, expo-speech-recognition) — Expo Go không chạy được. Bắt buộc build native ít nhất một lần. Branch làm việc: feature/rebuild-v2.

  1. yarn install — node_modules/ không được commit.
  2. Đặt 2 file config Firebase vào repo root: google-services.json (Android) và GoogleService-Info.plist (iOS). Cả hai đều gitignored (chứa API key — xem .gitignore). Nếu mất, tải lại bằng Firebase MCP tool firebase_get_sdk_config trên project visionvoice-app-2026 (hoặc Firebase console → Project settings → tải file config của từng app). app.json đã trỏ sẵn qua googleServicesFile.
  3. npx expo prebuild --clean — sinh lại /android và /ios (cả hai gitignored). Bước này copy file Firebase config vào native project và apply plugin (react-native-vision-camera, expo-speech-recognition, @react-native-firebase/app, @react-native-firebase/app-check, expo-build-properties).
  4. yarn android hoặc yarn ios (= expo run:*) — build và cài dev client lên máy thật. Test trên máy thật vì cần camera + mic.
  5. Đăng ký App Check debug token (bước hay quên nhất):
    • Ở build __DEV__, initFirebase() trong src/services/firebase.ts cấu hình provider 'debug'. Token không hardcode trong code — lần chạy đầu, native SDK tự sinh và in token ra native log: Android xem bằng adb logcat (lọc appcheck hoặc DebugAppCheckProvider), iOS xem trong Xcode console.
    • Copy token, vào Firebase console → App Check → Apps → chọn app → Manage debug tokens → Add debug token, dán vào.
    • Mỗi máy/emulator một token riêng — đổi máy là phải đăng ký lại.
    • Chưa đăng ký = mọi call Gemini bị 403 (App Check auto-enforced trên project này).
