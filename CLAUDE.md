## Project Overview

VisionVoice is a Vietnamese-language, voice-first assistive app for blind and low-vision users (graduation-thesis rebuild, v2, branch `feature/rebuild-v2`). Three features: (1) photo description — capture via voice "chụp ảnh" / volume key / shutter / gallery, resize + base64, send to Gemini through Firebase AI Logic, speak the caption; (2) multi-turn voice Q&A about the last photo (chat session — the image is sent once on the first turn); (3) on-device obstacle warnings — an expo-camera still-image loop (~0.9s) feeds ML Kit object detection, a bbox-area heuristic maps to safe/warning/danger, announced every 2–3s via TTS + haptics + full-screen color. Audio is half-duplex: speech recognition is hard-stopped while TTS speaks. Four screens via react-navigation native-stack. The old GRIT/ngrok backend is deleted (kept only as the thesis comparison baseline; legacy code: `git show master:src/screens/CameraScreen.tsx`).

**Tech Stack**: Expo SDK ~54 dev client (Expo Go NOT usable — native modules) · React Native 0.81.5 · React 19.1.0 · TypeScript 5.9 strict · @react-native-firebase/{app,ai,app-check} 23.8.8 (pinned — v25 needs a newer Xcode) · Gemini `gemini-3.6-flash` via Firebase AI Logic GoogleAIBackend (Spark plan, project `visionvoice-app-2026`) · @infinitered/react-native-mlkit-object-detection 5.0.0 · expo-camera / expo-speech / expo-speech-recognition / expo-audio / expo-haptics / expo-image-picker · @react-navigation/native-stack · AsyncStorage · jest-expo (jest pinned ~29.7)

## Code Style

### Language & Types
- TypeScript `strict: true` on top of `expo/tsconfig.base`. No `any` — `useDebounceCallback` uses `T extends (...args: unknown[]) => void`; follow that pattern.
- Exported API shapes use `interface` (`PreparedImage`); local unions use `type` (`type AppPhase = 'idle' | 'capturing' | ...`).
- Constants are typed by inference; only annotate when it adds information (`CAPTURE_KEYWORDS: string[]`).
- Numeric constants use readable separators: `API_TIMEOUT_MS = 30_000`.
- No new type casts — the codebase currently compiles with zero `as unknown as` casts; keep it that way.

### Components / Modules
- Functional components only. Screens: `export default function`. Everything else: named exports. No barrel files — explicit relative imports (`../services/gemini`).
- `StyleSheet.create({...})` at the bottom of the component file. All colors/type/spacing come from `src/theme/` tokens — never inline hex or raw fontSize.
- Hooks discipline: handlers wrapped in `useCallback` with correct deps; mutable non-render values in `useRef` (`cameraRef`, `soundRef`, `lastResetTimeRef`); every `useEffect` returns a cleanup that removes subscriptions, unloads sound, and calls `Speech.stop()`.
- **Accessibility is the product**: every `TouchableOpacity` gets `accessibilityLabel` and, where the action isn't obvious, `accessibilityHint` and `accessibilityRole`. Every state transition should produce audio (`Speech.speak`) plus haptic feedback (`Haptics.impactAsync` / `notificationAsync`).
- **All user-facing strings are Vietnamese** — UI labels, TTS phrases, voice keywords, and `console.warn` messages. Code identifiers stay English. Voice keyword lists include both accented and unaccented variants (`'chụp ảnh'` and `'chup anh'`) because ASR output varies.
- No magic values in components — tunables belong in `src/constants/config.ts`, every Vietnamese string in `src/constants/strings.ts`.
- Errors are contained, never fatal: `console.warn('Lỗi khi <action>:', err)`, speak a Vietnamese fallback via `speakExclusive`, return to idle.

## Project-Specific Cautions

- **Never call `Speech.speak` directly** in screens/components — all speech goes through `audioSession.speakExclusive()` (half-duplex invariant: the app must never hear its own TTS). `tts.speakAlways` is reserved for the Settings voice-test.
- **All user-facing strings live in `src/constants/strings.ts`**, tunables in `config.ts`, style tokens in `src/theme/` — no raw hex or fontSize in components.
- **Version pins are deliberate**: `@react-native-firebase` 23.8.8 (v25 requires a newer Xcode than SDK 54 images), `jest` ~29.7 (jest-expo compatibility). Don't bump without re-verifying builds.
- **MOCK_MODE** in `config.ts` returns canned Gemini answers after a fake delay — use it for UI work to save free-tier quota. Metrics tag mock responses so eval runs can't silently be mocks.
- **`console.log('VVMETRIC ...')` in metrics.ts is intentional** (adb logcat collection path for thesis metrics) — don't remove it.
- **The obstacle loop must keep deleting temp frame files** (finally block in useObstacleScanner) or the cache fills up during long sessions.
- **Adding a native/Expo module requires prebuild + rebuild**, not a Metro reload. Permission-bearing modules also need entries in `app.json` `plugins` + iOS `infoPlist` + Android `permissions`.

## Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked

- No "flexibility" or "configurability" that wasn't requested
- No error handling for impossible scenarios

## Working with Plan Mode (MANDATORY)

**Always brainstorm → plan → implement. No exceptions.**

1. **Brainstorm first**: Use the `brainstorming` skill to analyze the problem
   - Explore context, ask clarifying questions, propose 2-3 approaches
   - Present design and get user approval before writing a plan
   - Skip for trivial bug fixes (< 10 lines changed)
2. **Write plan**: Use the `writing-plans` skill to create a detailed implementation plan
   - Bite-sized tasks with exact file paths, code blocks, and test commands
   - Each step has `[Step] → verify: [check]`
   - No placeholders — every step contains actual code
3. **Wait for approval**: Do NOT implement until user says "ok", "go", "approved", "lgtm"
4. **Implement**: Follow the plan exactly, one step at a time
5. **Verify each step**: Run the check defined in the plan, loop until pass
